# ADR-7: Phase 7 — CLI, NuGet, optional FTS, benchmark report

## Status

Accepted (Phase 7)

## Context

Phases 0–6 delivered the embedded engine in-library only. Operators needed a small command-line tool for admin tasks, a packable NuGet artifact, optional full-text search for document fields, and a published comparison against SQLite and LiteDB on the page-file engine.

## Decisions

### Global tool `loah`

`LoahDB.Cli` ships as a .NET tool (`PackAsTool`, command name `loah`) with subcommands:

| Command | Purpose |
|---------|---------|
| `info` | Store metadata (`GetInfo`) |
| `check` | `CheckIntegrity` |
| `vacuum` | `Vacuum` |
| `backup export` / `backup import` | Zip backup/restore |
| `import-legacy` | `ImportLegacyV1` |

Shared flags: `--path` (base directory), `--root` (store name), optional `--key` for encryption.

`LoahCliApp.Run(args)` returns an exit code so tests can invoke the parser without spawning a process.

### NuGet

`LoahDB` sets `PackageId`, `IsPackable`, README in package, and semantic version `2.0.0` reflecting the page-file engine milestone.

### Optional full-text search

`EnsureFullTextIndex` + `SearchFullText` maintain an in-process inverted index (token → document ids) persisted in collection metadata. Tokenization is lowercase alphanumeric words (simple FTS, not stemming). Indexes rebuild on load and update incrementally on write.

### Benchmark report

`LoahDB.Benchmarks` supports `--quick-report <path>` to run timed scenarios at 10k documents (page-file LoahDB vs SQLite vs LiteDB) and emit a Markdown table. Full BenchmarkDotNet runs remain available via the default entry point.

## Trade-offs

- FTS is not on-disk B+Tree backed; large corpora should use external search.
- Quick report is indicative, not a substitute for local BenchmarkDotNet runs at 100k.

## Consequences

- New projects: `LoahDB.Cli`
- `docs/BENCHMARK-REPORT.md` generated by the quick report command
- Tests: `LoahPhase7Should.cs`
